# Reviews (stage 8): what the core had to change

The core rebuild (stages 1–3) had no extension points, no `modulesOff`, no Features page, no MCP door and no single save. Reviews' rules and pages also lived inside the core (stage 3 needed them for home.csv and navigation.csv). Every change below is a finding: the earlier stages should have built it. Originals are in `rebuild/local/core-before/`.

| Core file | What changed | Why |
|---|---|---|
| `modules.mjs` (new) | The registry: `register`, `isOn` (from `Workspace.modulesOff`), `routeOwner`, `toolOwner`, `refuser`/`refusalFor` (a module's `writes` rule run on every save), `extFor` (R.ext), and the three switched-off sentences (page, action, AI tool) | The kit's module table names extension points (routes, navigation, places, AI tools, help) but stage 1–3 never asks for them, so the core had none |
| `modules/installed.mjs` (new) | The list of modules this build has | Both the drill (`main.mjs`) and the app need the same set |
| `stage3.mjs` | Menu row and phone tab come from registered modules (`offOf` reads `opt.off` or `W.modulesOff`); tabs are filled Home, Check-in, Goals, module tab, then People, Activity; a module's addresses get `pageName`/`litItem` from the module, and "Page not found" while off; `?review=` page names via `goalParam`. Home's review lead, the check-in lead on a review's day, a question's due date and the deadline words now come from `R.ext` (the module), with plain words when absent. With no review module (or it off), someone who owns no goal is led to "Goals you watch · {n} need attention". `asksWaiting` now keeps a next step you agreed for yourself. `reviewById`, `meetsIn`, `reviewDay`, `reviewHeld` left the core | Reviews' rules were in the core; home.csv still 56/56 and navigation.csv 60/60 with the module loaded |
| `main.mjs` | Loads `modules/installed.mjs` before stage 3 and calls each module's `drillFiles` (Reviews writes `reviews.csv`) | stage 3's conformance assumes Reviews is there; reviews.csv needed a writer |
| `drill.json` | `"also"` gains `"reviews"` | as the conformance README says (but see GAPS R-1: the harness ignores it) |
| `app/server.mjs` | One `save(ctx, commit)` (upsert + change log) that every Reviews write and the core's ask actions go through, refused by a switched-off module's `writes`; route dispatch to modules (closed page with the module-off sentence while off; `?review=` redirects to the goal); POST dispatch; `/workspace/features` (switches, read-back dialog, Undo, logged, `W.switches` kept for "moved while off"); `/api/mcp` tool door; Help hides a switched-off module's article and its address says so; goal page places (walk bar and decide area, `goalAside`), History's Reviews filter (names linked only while on); an ask's "by {first name} in {review}" only while on; Home: `data-part` on the lead, the watch lead's See them, the module's lead button and ring, the glance cell place, Needs your response grouped by kind ("Questions for you"); receipt words from `R.dueWords`; Goals' module filters (`inreview=`); workbook/JSON export and import preview with module hooks; `/__reset` resets switches; picker goal rows say the status word first; removed the core's own `/reviews` pages and its `mark` POST | the core had no Features page, no MCP server, no export, no single save and drew Reviews itself |
| `app/tools.mjs` (new) | Core AI tools: `describe_system`, `get_goal` (no notes while off), `list_requests` (review named only while on), `edit_call`, `export_json` | the core had no MCP server; criteria 4 and 9 need `edit_call` and the tools' sentence |

Files changed: 4 existing core files (`stage3.mjs`, `main.mjs`, `drill.json`, `app/server.mjs`) plus 3 new core files (`modules.mjs`, `modules/installed.mjs`, `app/tools.mjs`).
