Each stage's folder, `standin/<stage>/`, has `REPORT.md` ((a) ported, (b) rewired, (c) platform requirements NAMED/GAP, (d) behaviour, one-line kit fixes) and a patch: `core/core.patch` is against the pin (dfe97c0e); each module's `<m>.patch` is against the core stand-in. To rebuild one locally: `git archive dfe97c0e | tar -x -C X`, `git apply core.patch`, commit as core-standin, `git apply <m>.patch`, `npm ci`. Built folders and packs lived in the old session's scratchpad only.

Practicalities learned: subagents can't write REPORT.md (their tool refuses report files), so ask for the report as the reply and save it yourself; `rsync` isn't installed, so copy with tar and check `pwd` before every git or npm command (three builders ran `npm ci` in the main checkout by mistake; nothing tracked changed); with four builds at once, `npm test` times out at 5 s, so run it with `--testTimeout=60000`.
