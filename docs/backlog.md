# Backlog

Lane's ideas and the follow-ups found along the way, in the order they should be built. A new idea is added here first, never built straight away; it is built when Lane picks it or approves the next item.

**What Faro is for (Lane, 8 Nov):** a model for an internal application to copy, plus demos and an off-site to play with. It never holds real company data. So an item is built only if it shows the rebuild something worth copying (a product idea, a rule, a screen pattern); what the internal platform provides anyway (sign-in, single sign-on, scale, backups, observability) is written into the spec as a requirement instead (8r).

**Order (Lane, 8 Nov):** N and the metric library back end (0b) before the talk, its screens built live on Wednesday; after it, 8g, then 0c (own database project: the one real risk left), 8c (swappable parts: what makes copy-and-adapt real; built 9 Nov), the Goals page (G, the search hotfix, then GP: Lane 9 Nov), 0a, L, GD, NAV, MAP, one small batch (0u, 7, 10a, R5), 3a, 0t, 11. Wednesday's feedback can still change it.

**How items are ordered:** by what they unblock first, then value against effort. Effort: S (under a day), M (a release), L (more than one release).

**In progress (9 Nov, evening):** merged today: 8c (#58), live-build kit (#56, #60), G (#61), the Goals search hotfix (#62), the goal-page hotfix (#63). Merged since: R (#64), 8g with drill 2 (#59, 100% from the kit). Building: GP, WS.
