# Core files changed for the spreadsheets module

A core that needed changing for a module is itself a finding. Seven of the nine changes are things stages 2 and 3 should already have built. The other two only switch the drill on and off. Originals are kept in `rebuild/local/` (`engine.orig.mjs`, `server.orig.mjs`, `help.orig.mjs`).

| # | File | What changed | Why | Which stage should have built it |
|---|---|---|---|---|
| 1 | `rebuild/modules/index.mjs` (new) and `app/server.mjs` | **The core's extension points.** There is a registry of modules. Each module has an id, a name, what it does, its routes, its old addresses, its places on core screens, its Help articles and its AI tools, plus `isOn(W, id)` from `modulesOff`. The server now does five things. (a) It dispatches a module's routes and old addresses, and both are Page not found while the module is off. (b) It gives the module a helper object H: layout, send, redirect, log, bump, nameOf, and the goals a Goals address shows. (c) It adds `ctx.on`, `ctx.S1`, `ctx.wsId` and `ctx.wsPath`. (d) It adds the places `goals.tools` (inside a new `.goals-toolbar`), `data.tools` (inside a new `.data-tools`) and `activity.import`. (e) Activity folds an import's rows under its summary, with a "Show the N changes" disclosure and a `kind=imports` filter. | The core had no extension points, no `modulesOff` handling and no places for a module to fill. | Stage 3, and the architecture's "modules register into the core's extension points" |
| 2 | `app/server.mjs` | **Workspace → Features** (`/workspace/features`). There is a switch per module with what it does. An admin flips it, and it says "{Module} is off in {workspace}." with Undo, which then says "{Module} is back on." The change is logged ("switched Spreadsheets off"). Someone who isn't an admin sees no switches. Workspace's About links to it. | No Features page existed. U48 needs one. | Stage 3 (help: "Features: switching parts of Faro on or off") |
| 3 | `app/server.mjs` | **A small MCP server.** `POST /mcp` takes JSON-RPC with two methods. `tools/list` lists the core's `set_feature` and every module's tools. `tools/call` refuses a tool whose module is off, using the module-off sentence. The token is `Bearer <person id>`, because R1 (sign-in and tokens) is the platform's job. | There was no MCP server at all. | Stage 3 / stage 4 (AI access) |
| 4 | `app/help.mjs`, `app/server.mjs` | Help keeps each article's `##` section and lists articles under their sections, so "Data in and out" stays when Spreadsheets is off. A module's articles get the module's ids (`import`, `export`, `columns`, `past-imports`), are hidden while it is off, and their address then says "Spreadsheets is switched off in …, so its Help isn't shown there." A module can supply an article's HTML: `columns` is the field table. | Help had no sections, and no idea that an article belongs to a module. | Stage 3 |
| 5 | `engine.mjs` | `SHEETS` is exported, so the import reads headers by the same names and other names as the engine. | The module must know which headers a sheet reads, to name the columns nothing reads. | Stage 2 (one format, defined once) |
| 6 | `engine.mjs` | Four fixes, each shown by loading an unedited workbook back. (a) A non-admin is refused only for a People row that *changes* someone. Before this, every unchanged People row was Must fix, so no non-admin could load a full workbook (U94). (b) "Keep the name to 80 characters" applies only to a new name or a changed one. The demo's G-48 is 141 characters long. (c) A row that says Stop with every other cell as the goal already has it isn't "changing the goal" (U46). (d) A People row whose Action says Example is left out, as on Goals. The engine never read People's Action, so the template's example person was refused. | A downloaded workbook must load back unchanged (exit criterion 4). | Stage 2 |
| 7 | `engine.mjs` | New IDs carry a tag for the run (`input.idTag`). The module passes one tag per import, and the drill's `_cN` IDs stay the same. | Every run numbered from `_c1`. The second import of new goals overwrote the first import's goals (found by criterion 14: 5,126 goals where 6,126 should be). | Stage 2 (new IDs) |
| 8 | `main.mjs`, `app/server.mjs` | `FARO_MODULES_OFF=spreadsheets` sets `W.modulesOff` for a run, and `/__reset` keeps it. | It runs the drill and the core journeys with the module off. | (Drill support only) |
| 9 | `app/server.mjs` | `.data-tools` has a minimum height of 44 px. | An empty toolbar has no height, so with the module off U48's ".data-tools shows" check fails. | (Cosmetic) |

The harness after these changes is 100%, with the module on and with it off (`node spec/rebuild/drill.mjs rebuild`, and with `FARO_MODULES_OFF=spreadsheets`). The scores are 318,703 of 318,703 cells and 14 of 14 store contracts. The core's scripted journeys are the same 13 DONE and 5 PART with the module on and off.
