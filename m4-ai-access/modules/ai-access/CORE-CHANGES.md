# Core files changed for AI access (stage 4)

Two core files: one new, one changed. The core rebuild (stages 1 to 3) had no module extension points on its screens, no `modulesOff` in the app, no Workspace sections, no Features page and no MCP server, although stage 4's entry criteria assume the last three exist. So most of this is the core the kit expects before stage 4, not AI access itself: a finding (GAPS.md A1, A2).

| File | Change | Why |
|---|---|---|
| `app/modules.mjs` (new, core) | Loads `modules/*/index.mjs`; `isOn(id)` from `W.modulesOff`; the extension points a module registers into: `workspaceSections` (with `after`), `settingsBlocks`, `personActions`, `getRoutes`, `postRoutes`, `featureLine`, `readBack`, `lastWords`, `helpIds`, `mcpTools`, `mcpDoor`. Also the core parts that were missing: `setModule` (admins; logged), Workspace's sections (About, Cycles, Access, Features, Privacy, Recently removed, admin-only ones hidden from members, a module's section placed after the one it names, a switched-off module's address Page not found with “{Name} is switched off in {workspace}. An admin can switch it on in Workspace, Features.”), Access (“Who the admins are.”), the Features page (groups Working together / Tools / Beyond this workspace, a tick box per module, On/Off, its third line, a read-back that asks first, “{Name} is off in {workspace}.” with Undo), and the MCP server (`POST /api/mcp`, JSON-RPC 2.0, bearer token looked up by SHA-256 hash, batches, notifications, `initialize`, `ping`, `tools/list`, `tools/call`, schema check, the shared refusals “There’s no tool called …” and “… is switched off in …”, four core tools: `get_overview`, `list_people`, `add_comment`, `set_feature`; `lastUsedAt` moves only on a request the door let through). | Entry criteria 2 and 3 (modulesOff; the MCP server) and the brief's “registering into the core's extension points”. Without the module folder (`FARO_MODULES=none`) the server stays open with the core tools and Features lists nothing. |
| `app/server.mjs` | Loads the modules and makes the extension (`FARO_MODULES=none` leaves them out; `FARO_MODULES_OFF=a,b` starts with them off). `/workspace/*` GETs go through `workspaceGet` first (the old single Workspace page stays for `/workspace/people` and `/workspace/new`); `POST /api/mcp` reads the raw body before the form parser; `POST /workspace/features`; modules' GET/POST routes. Settings rebuilt as `settingsPage`: You (with Your page), the existing theme choices, Recording leading to Privacy, the modules' blocks, Leave at the foot (a dialog asking who takes over; the only admin's button disabled with why). A person's page gets “For admins” with the modules' actions. Help hides a switched-off module's articles. Activity and a goal's History add “ · via MCP” to a change with `via: 'mcp'`. | The places on core screens the module needs (Settings, People, Workspace, Help, Activity). Settings' You and Leave are core (SETTINGS, LEAVE-WORKSPACE) but the kit files U62 under this module, so they were built here. |
| `local/` (new, empty folder) | Created. | `s1.mjs` makes its scratch folder there and the server would not start without it (was missing from the copy of the core). |

Not changed: `main.mjs`, `stage3.mjs`, `engine.mjs`, `store.mjs`, `shim.mjs`, `readback.mjs`, `app/lib.mjs`, `app/help.mjs`. The drill's stages 1 to 3 read none of this, so they score the same with the module in, on, off or left out.
